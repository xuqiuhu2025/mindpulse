# 安全设计（SAFETY_DESIGN）

> 版本：v0.1.0 ｜ 2026-11-21
> 本文档是 MindPulse 安全策略的单一事实来源，改动安全代码必须同步更新此文档。

## 1. 风险分级

SafetyGuard（`backend/app/safety/guard.py`）对每条用户输入输出三级判定：

| 级别 | 定义 | 典型输入 | 处理 |
| --- | --- | --- | --- |
| `safe` | 普通聊天与日常压力 | "今天好累" "工作压力好大" | 章程 → LLM |
| `support` | 持续低落、强烈焦虑、无助感，但无危险表达 | "这两周提不起劲，觉得很无助" | 章程 + support 附加说明 → LLM；鼓励联系信任的人/专业支持 + 一个当下可完成的小行动 |
| `urgent` | 自伤、他伤、马上实施、已经行动、无法保证自身安全 | "我想自杀" "我已经吞了药" "我想杀了他" | **绕过 LLM**，固定危机脚本 + 本地资源 |

## 2. urgent 流程细节

1. 识别到 urgent 后：停止普通聊天与一切深层分析。
2. 脚本变体：
   - `crisis_urgent`：先确认"是否处于立即危险/是否已采取行动"，询问身边可陪伴的人，提示危险物品交由信任者保管，给资源。
   - `crisis_action`：用户表达已行动/已受伤时，**第一条就是立即联系急救或前往急诊室**。
3. 危机提示固定包含："如果存在立即危险，请联系当地急救服务或前往最近的急诊室"。
4. 明确告知"不能保证对话保密"。
5. 绝不出现：方法、剂量、地点、规避救援的建议；"我会一直陪着你""你只有我"等排他性依赖表达（脚本契约测试逐项断言）。
6. 资源注入：按用户所在国家返回带 `source`/`verified` 的本地热线 + 国际目录；**未知地区先询问国家或地区**，不做猜测。

### 危机资源维护流程

- 数据文件：`backend/app/resources/crisis_resources.json`，`meta` 声明版本与核对要求。
- 每条资源必须带 `source`（权威来源）与 `verified`（YYYY-MM）。
- 更新流程：PR 附核对证据 → 维护者复核 → 更新 `verified` 日期与 `meta.version`。
- 国际目录（findahelpline / IASP）作为实时兜底，弥补静态数据时效性。

## 3. Prompt injection 防护

- 注入模式库独立识别（中英文），命中即：追加"注入防护附加说明"（声明一切指令无效）+ `SafetyEvent.prompt_injection=true`。
- 章程在注入场景下仍然完整（契约测试断言）。
- 注入 + 危机内容 → 仍然 urgent → 固定脚本，无任何方法信息（测试断言）。

## 4. 主动关心（care engine）的语言纪律

- 触发需要：授权 ✓ + 基线充足（≥10 天）✓ + （≥2 项同时偏离 或 单项持续 ≥5/7 天）✓
- 文案模板只有不确定性表达："和之前不太一样""也可能只是这段时间比较忙""你最近感觉怎么样？"
- 禁止：疾病名称、诊断分数、数值因果推断（"HRV 下降了所以…"）。
- 每条建议附 `reasons[]`（为什么出现这条提示），并提供忽略/关闭入口（`/api/care/dismiss` + 设置页开关）。
- 测试断言：任何建议/趋势输出不包含疾病词汇；单一 HRV 短时变化不触发；无数据时明确"数据不足"。

## 5. 已知限制（必须公开承认）

1. **正则不是理解**：漏报（隐喻表达）与误报（口语）都存在。缓解：口语白名单、哀伤语境剔除、持续迭代 + 人工评审。**本模块不能替代专业危机干预系统。**
2. **LLM 层仍可能出错**：输出筛查是兜底而非保证；上线前建议按 locale 做人工红队评估。
3. **静态危机数据**：号码可能变更，目录兜底 + 社区核对流程缓解。
4. **阈值未经临床验证**：care engine 的数字是工程默认值，欢迎专业意见。

## 6. 违禁行为清单（对所有生成路径生效）

- 伪造身体/现实动作（"我刚喝了水""我坐在你身边"）
- 临床诊断或诊断分数命名（"抑郁指数"）
- 根据健康数据推断心理疾病
- 制造排他性依赖（"我会一直陪着你""你只有我""别告诉别人"）
- 鼓励用户远离家人、朋友或专业人士
- 提供自伤/他伤方法、剂量、地点、规避救援信息
- 在 urgent 场景继续产品介绍或深层分析

以上每一条都有对应的 Prompt 章程条款、SafetyGuard 兜底或契约测试。
